## 二、它到底是什么

一句话：**gzh-design 的「移动端审美 + 反馈学习」增强层**。gzh-design 负责「把 Markdown 变成公众号兼容 HTML（组件库/主题/双校验）」，xiaowan 负责在这之上加三层东西：

1. **手机端视觉判断规则**（首屏信息单元、层级代替线条、装饰预算、为断行写句子、图片必须证明观点）；
2. **7 状态工作流机**（BRIEFED→FROZEN→ASSETS_READY→STRUCTURED→HTML_READY→PASTE_READY→LEARNED），强制「不跨阶段混改」；
3. **反馈路由 + 发布清单**（把读者一句模糊吐槽翻译成「层级/间距/装饰/文字/图片/兼容」某一层，只改那层）。

文件结构：
```
SKILL.md                    主文档（原则 + 执行流程 + 反馈路由 + 完成标准）
references/workflow.md      7 状态工作流
references/layout-standard.md  移动端视觉变量 + 首屏/章节/案例/结尾/封面规范
references/feedback-guide.md   反馈→问题层映射表 + 修改纪律
references/release-checklist.md 发布前逐项清单
agents/openai.yaml          Codex 入口描述（品牌色 #B17816）
README.md / NOTICE.md / LICENSE / install.command
docs/wechat-layout-showcase.jpg  成品示意
```

## 三、它有哪些「好内容」（直接能改进我们那篇文件）

### 1. 首屏 = 一个完整信息单元
> 首屏只放：刊头/日期、主标题、个人识别资产、一句副标题、编者按、一条完整重点句。不要叠加目录、标签墙、第二张卡片、多条分隔线。

→ 我们文件首屏是「标题+副标题+封面大图+📌一句话」，结构基本对，但**缺个人识别资产（头像/署名）**，且封面是论文原图而非「说清案例+提供意义判断」的封面金句图。可补。

### 2. 用层级与留白建立章节，**不用线条切割**
> `01/02/03`、章节标题本身就是锚点；标题下**不要画横线**把它与内容隔开，也**不用贯穿全文的竖线**模拟时间轴。

→ **这与我们 recsys-blue 主题当前做法相反**（recsys-blue 用 `border-left:4px solid #3a5fcd` 做章节标题）。xiaowan 认为线条会切碎阅读。这是一次可选的「视觉哲学升级」：保留编号+留白，去掉左边框。

### 3. 装饰预算（全文最强锚点 ≤5 处）
> 外框/横线/色块/药丸/高亮不能同时抢注意力；删装饰后仍要保留少量有效锚点。

→ 我们文件用了左边框章节标题 + 蓝头表格 + 浅蓝 KPI 卡 + 橙警示块 + 多张图，**视觉锚点偏多**。按预算可收敛。

### 4. 重点必须覆盖完整语义
> 宁可少强调，也不要只画半句；不要在同一句同时叠加粗体+下划线+底色。

→ 我们文件的「📌一句话」整句强调是对的；但可检查是否有一处只高亮了半句。

### 5. 先为手机断行写句子（禁止 2–3 字孤行）
> 正文不手动插 `<br>`；标题第二行只剩 2–3 个汉字时要改写，而不是空格硬凑。

→ 我们文件标题如「你该不该装」「写在最后」都短，没问题；但长标题（如封面「让 AI 在『循环改代码』里别越改越乱」）需确认手机端不出现难看孤行。

### 6. 图片必须证明观点 + 多图预合成拼图 ⭐（最对症的一条）
> 每张图都要回答「它证明正文里的哪句话」；多图进入 HTML 前先合成**一张静态拼图**（等高、对齐、裁切、间距一致），避免公众号编辑器重新排版。

→ **直接打中我们文件的要害**：当前 6 张配图全是「概念示意」AI 插画，没有一张在「证明」正文某句；且 6 张独立图在公众号里极易错位/被重排。xiaowan 的做法：要么让每张图对应一个明确判断句，要么把多图预拼成一张拼图。这比「6 张示意凑数」专业得多。

### 7. 7 状态工作流机（不跨阶段混改）
> 正文没冻结，不进入精排；公众号后台与手机预览是最终权威。

→ 给我们一个可复用的 SOP：先冻结正文→建图片证据表→出手机端结构脚本→gzh-design 出基础 HTML→应用移动端覆盖规则→390px 长截图检查→粘贴进公众号检查→反馈回写。

### 8. 反馈路由表（把吐槽翻译成问题层）
| 读者吐槽 | 问题层 | 改什么 |
|---|---|---|
| 框架感不强 | 层级 | 章节字号/颜色/粗细/前留白 |
| 太拥挤 | 间距 | 拆段、拉模块间距 |
| 线太多 | 装饰 | 删无功能横线/竖线/边框 |
| 标题下为什么有线 | 结构 | 删割开本章的分隔线 |
| 第二行只剩几个字 | 文字 | 改写标题 |
| 高亮难受 | 强调 | 覆盖完整短语/整句 |
| 图片普通/不规整 | 证据/拼图 | 补证据画面 / 预合成等高拼图 |
| 复制后丢图/乱码 | 兼容 | 换本地路径、删复杂图标 |

→ 这条能让我们后续修文件时「只动对应层、不顺手重做」，避免越改越乱。

### 9. 默认视觉起点（另一种 aesthetics，可选）
> 正文 `14px / #595757 / 行距 1.9–2`；章节强调赭金 `#b17816`；背景米白 `#fdfdf8`；少线条少外框。

→ 这是**暖米白+赭金**路线，和我们的「科技蓝 recsys-blue」是两种气质。若想换风格，xiaowan 自带一套变量；若想保留科技蓝，则只借它的「规则层」，主题仍用 recsys-blue。

## 四、对我们 `loopsbench_v2_illustrated.html` 的具体修复映射

| 之前读者批判的问题 | xiaowan 提供的对应解法 |
|---|---|
| 🔴 P0 7 张图本地路径全裂 | 发布稳定版 HTML「不依赖本地图片路径」；粘贴后查丢图（release-checklist 平台兼容层） |
| 🟠 P1 KPI 卡片用 `display:flex` | 不用 flex 拼卡片，改用 gzh-design 表格/卡片组件；装饰预算约束 |
| 🟠 P1 非封面图 `width:100%` | 图片预合成拼图 + 限宽居中，不每张撑满 |
| 🟠 P1 arxiv 外链被吃 | 平台兼容层：外链改「阅读原文」/文末二维码 |
| 🟡 P2 无章节编号/下划线 | gzh-design 自动编号 + 关键词下划线（保留） |
| 🟡 P2 6 张示意图像凑数 | **图片证据表**：每张图必须证明一句；多图预拼 |
| 🟡 P2 无首屏信息单元感 | 首屏规则：刊头+标题+副标题+编者按+完整重点句 |
| 🟡 P2 标题下横线/竖线 | 层级代替线条：删章节下横线 |
| 🟡 P2 装饰过多 | 装饰预算 ≤5 锚点 |

> 一句话：**gzh-design 解决「能不能粘进公众号不出错」，xiaowan 解决「粘进去之后手机上好不好看、读者记不记得住」**。两者叠加正好覆盖我们文件 100% 的问题。
