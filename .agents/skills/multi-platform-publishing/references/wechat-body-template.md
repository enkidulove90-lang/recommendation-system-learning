# 微信公众号正文模板（微信风味纯文本）

> 配套 `redbook/automation/paper_to_wechat.py::render_wechat_article`。
> 公众号 UEditor **不渲染 Markdown**，正文必须是**不含 `**`/`##`/`---` 的纯文本**。
> 本模板用 emoji 分段标记 + 空行 + `「」` 强调制造层级，复制即用。

## 硬约束（必读）

| 约束 | 值 | 说明 |
|------|-----|------|
| 标题 | ≤64 字 | `WeChatDraftPayload.validate` 强制 |
| 正文 | 200–2,000 字 | 下限 200（公众号偏好深度），上限截断 |
| 作者 | ≤8 字 | 超出截断 |
| 摘要 | ≤120 字 | `textarea#js_description` |
| 封面 | 1 张 | 取 `images[0]`（架构图优先） |
| 严禁语法 | `**` `##` `---` `![` | 会被渲染成字面字符 |
| PDF | 不支持附件 | 仅放 arXiv 链接 |

## emoji 分段标记约定

| 标记 | 含义 | 用法 |
|------|------|------|
| `🔹` | 行动 / 方法 / 建议段 | 它过去解决了什么、新方法、分人群、写在最后 |
| `🔸` | 背景 / 约束 / 局限段 | 开场钩子、最先没必要的几类、但不等于全删 |
| `💡` | 关键结果 | 紧跟指标的亮点数字 |
| `📚` | 参考文献 | 文末链接块 |
| `🧑‍🎓` / `💼` / `🔬` | 分人群前缀 | 学生 / 工业界 / 研究 三种读者 |

## 骨架（逐段，空行分隔，零 Markdown）

```
🔸 <one_line_summary：一句话结论>

但在此之前，<task_type / input>长期是绕不开的痛点。


🔹 它过去解决了什么

任务类型：<task_type>
输入：<input>
<one_line_summary>。


🔹 新变化把旧方案吃进了模型

1. <innovation[0].point>
2. <innovation[1].point>
3. <innovation[2].point>

💡 关键结果

<benchmark.main_results>（与上文创新点去重，避免重复）


🔸 最先没必要的，是这几类

· <limitation 句1>。
· <limitation 句2>。


🔸 但这不等于全部都该删

本文方法在 <datasets> 上得到验证。
但上面列出的局限提醒我们：新方法不是「全盘替代」，而是按场景取舍。
简单任务不必套重流程，复杂或高风险任务仍值得保留显式约束。


🔹 新方法：先裸跑，再加最小Skill

第一步：先定义结果，不定义仪式——把目标、硬约束、验收标准写清楚。

第二步：用基准数据（<datasets>）让模型/基线裸跑，记录成功率与返工。

第三步：只看可复现的失败——同一类错误稳定出现，才说明缺经验。

第四步：只补一个最小补丁——把上文方法（<innovation[0] 前30字>…）固化成可触发的最小流程。

第五步：再跑同一组任务，对比指标（<metrics>）；质量没提升就删掉。


🔹 还要不要装

🧑‍🎓 如果你是在校学生：先吃透上面的创新点，理解它到底解决了什么。

💼 如果你在工业界落地：重点看关键结果能否在你的业务指标上复现。

🔬 如果你在做研究：借鉴它的模块拆分思路，而不是照抄整条流程。


🔹 写在最后

<one_line_summary>。
真正该学的，不是最火的插件或 Skill 名字，而是看清模型现在会什么、不会什么。


——————————————

📚 参考文献

· 论文：https://arxiv.org/abs/<paper_id>
· PDF：https://arxiv.org/pdf/<paper_id>
· 代码：暂无官方代码（以论文复现为准）

> 图表摘自论文，仅作学术解读。
```

## 行内强调替代方案

| Markdown | 微信风味 | 备注 |
|----------|----------|------|
| `**重点**` | `「重点」` | 用 `「」` 包裹 |
| `## 标题` | `🔹 标题` | 用 emoji 标记，前后空行 |
| `- 项` | `· 项。` | 用 `·` + 句号 |
| `1. 项` | `第一步：项` | 用中文序数更自然 |
| `---` | `——————————————` | 不要用 `---` |
| `![图](x)` | 走封面/HTML `<img>` | 正文不支持图片 |

## 自检清单（render 后必过）

- [ ] 全文中搜索 `**` → 0 处
- [ ] 全文中搜索 `## ` → 0 处
- [ ] 全文中搜索 `---` → 0 处（允许 `——————————————`）
- [ ] 含 `🔹`/`🔸`/`📚` 至少各 1 处
- [ ] 字数 200 ≤ len ≤ 2000
- [ ] 所有数字/模块名/公式号可在 11 维摘要 JSON 定位（无幻觉）
