# LightGCNpp idea2 · 项目 Idea 总结

> 状态：2026-08-11。E11_ultra (EP=100) 已重启并在跑；E3/E12 hook 已备好待判定。

## 一句话 Idea
**冻结跨模态融合门控权重 `c=0.8`（不学习它），保留对比式知识对齐模块，多模态 LightGCN++ 在 amazon-baby 上比纯 ID 基线 R@20 +4.5%（EP=20）/ +6.9%（EP=50）。增益主要由文本模态驱动，图像对齐在文本之上再带来跨模态协同。早期"学习门控权重"的方向是死路——它会塌缩成纯 ID 且丢失档位区分度。**

## 背景与方法
- 基模型 **LightGCN++**（LightGCN + 多模态特征）。
- **idea2 模块**：把 image/text 知识经投影 + 对比损失对齐进 ID embedding，由一个门控 `c` 融合：
  `h = (1-c)·h_id + c·h_mm`。
- 核心可调量：`c`（融合比例）、`mm_reg`（对比损失权重）、`layer`（GCN 层数）、`mm_proj_refresh`（投影刷新频率，锁 **32**，禁用 `mm_eval_fresh`——后者 train/eval 不一致会直接崩 R@20）。

## 实验脉络（关键证据）

### E1 — 固定 c 扫描（EP=20，全模态）
锁定 `c ∈ {0.3, 0.8, 1.0}`：
| c | R@20 | vs 纯ID基线(≈0.0842) |
|---|---|---|
| 0.3 | 0.08508 | +1.1% |
| **0.8** | **0.08798** | **+4.5%（最优）** |
| 1.0 | 0.08721 | +3.9% |

→ `c=0.8` 是固定门控的经验最优点。

### E2 — 去掉 conf_reg（软约束）
验证"是不是 conf_reg 把 c 推向极端"。结果：去掉后 c 仍从 0.38 塌到 **0.005**，R@20 仅 0.0847（< c=0.8）。
→ **conf_reg 不是元凶**；BPR 梯度在局部偏好丢弃多模态（短期收益），全局最优却在 c≈0.8。

### E6 — 学习 c（Lagrangian 预算 / 对偶上升）
试图用硬预算把 c 钉在 0.8 并学习它。
- **机制 PASS**：FRESH conf = 0.796（std 0.216，未退化成 force_c），预算精确命中 0.2/0.6/0.8 三档。
- **效果 INCONCLUSIVE**：A(学 c)=0.08283 vs A0(force_c 0.8)=0.08740（-5.2%），但 A 的逐 epoch 斜率更陡、末段仍在爬。
- **决定性发现**：c_target 三档全部命中预算，但 R@20 **非单调**（t0.2≈0.083≈t0.8，t0.6 掉到 0.0787）；且软惩罚 λ=1 与 AL 对偶几乎等价。
→ **学 c 时档位区分度消失**（对照 E1 固定 c 时三档区分明显）；"自适应 c"这一增量价值 ≈ 0。

### Phase B 决策
**放弃学 c → 锁 `force_c=0.8` → 转去验证对齐模块本身**。

### E8 — 单模态消融（EP=20，c=0.8）
| 模态 | R@20 |
|---|---|
| 仅图像 | 0.0772（甚至低于纯 ID 基线 0.0842！） |
| 仅文本 | 0.0853 |
| 全模态(c=0.8) | 0.08798 (EP=20) / 0.09004 (EP=50) |

→ 增益主要由**文本**驱动；图像单独用反而有害。但全模态 > 文本-only（+5.6% 相对）→ 对齐模块带来**跨模态协同**（图像在文本之上再增益）。

### E11 — 全模态 c=0.8 长训（EP=50）
- 三 seed 均值 **0.09004**，比 EP=20 口径靶子 0.08740 高 **+3.0%**。
→ EP=20 是欠训练、非天花板；c=0.8 在更长训练下增益更大。

## 已坐实的结论
1. **方法**：LightGCN++ + idea2 对比对齐 + 固定 `c=0.8`。
2. **增益**：+4.5%（EP=20）/ +6.9%（EP=50）vs 纯 ID；文本主导，图像提供跨模态协同。
3. **已证伪的方向**（踩坑）：学习门控 c（E6）→ 塌缩 + 丢区分度；去掉 conf_reg（E2）→ 不解决塌缩；`mm_eval_fresh` → train/eval 不一致崩 R@20。
4. **未决**：EP=100 是否仍爬升（E11_ultra 进行中）。

## 口径铁律（防假阴性）
- 一律 `--mm_proj_refresh 32`（`_pr32`）；**绝不** `--mm_eval_fresh`。
- 判 c 塌缩只看 `FRESH conf_mean` / `batch_c` / `budget_loss`，**不看**缓存的 `[idea2] conf_mean=`（滞后 +0.6）。
- eval txt 列序：N@20, N@40, **R@20**, R@40, P@20, P@40 → R@20 取第 3 列。
- 单训练进程纪律：~1.1GB/进程；空闲 <2GB 触发沙箱静默 OOM kill，**严禁并行两训练**。
- 进程去重 / 启动守卫：框架后台会起 2 份副本，靠 `dedup_runners.ps1`（只杀"根"训练进程、递归杀整树）+ `guard_ultra.ps1`（已有同键根或已完成则禁止启动）保证单实例。注意 bash 内 `powershell.exe` 须用 Windows 路径且只能在后台任务上下文调用（前台被安全策略拦截）。
