## 1. 一句话目标

> 在 PRISM 否证后的真空中，用 **MMEACR 的属性引导记忆**（替代 L_syn 的角色）与 **RRF 双轨融合**（补齐排名层融合），把"多模态特征包含推荐信号（C5）但模型学不到最优"这一矛盾，变成两条**机制可归因、CPU 可跑、R@20 可判**的实验线；DeepSeek 提供 LLM 轨的落地能力。

## 2. 实验矩阵（按优先级排序，全部 CPU 可跑）

### M1 ⭐ RRF 双轨融合（P0，最优先，零训练纯排序）

| 项             | 内容                                                                                 |
| ------------- | ---------------------------------------------------------------------------------- |
| **目标**        | 验证"排名层融合"能否拿到 C5 中模型自学不到的最优（c≈0.8 的融合增益）                                           |
| **机制**        | 两轨排序 → 倒数秩融合：`S_RRF = 1/(k+rank_1) + 1/(k+rank_2)`，k=60（MMEACR 默认），等权起步            |
| **轨 1（CF 轨）** | LightGCN++（NLGCL 增强基线）打分排（现成，无需重训）                                                 |
| **轨 2（内容轨）**  | SBERT/CLIP 融合特征与用户历史均值 e_u 的余弦相似度排（`docs/mmeacr_code_design.md` P2，零外网）            |
| **关键配置**      | 融合前两轨各自归一化；k∈{40,60,100} × w∈{0.5,1.0} 扫描；决策门：融合后 R@20 ≥ max(单轨) + 0.5%（防过度工程）     |
| **实现落点**      | 从 `AgentCF_Test_log-.py:294 rrf_fusion` 移植 ~15 行；评估钩子挂在现有 `run_idea2.py` 的 test 阶段 |
| **依赖**        | NLGCL 模型权重（现成）+ amazon-baby-mmssl 特征（现成）                                           |
| **成功判定**      | 双 seed 平均 R@20 相对单轨最优 +2%（对齐 idea1 的 3% 阈值放宽，因 RRF 是零训练机制）                         |

**为什么排第一**：零训练、零 LLM 依赖、代码 15 行、收益确定性最高；同时为 M2 的 e_u 画像提供"第二轨"载体——M1 的轨 2 若直接用 e_u 画像，则 M1 与 M2 的画像部分互相验证。

### M2 ⭐ 属性引导记忆（P1，核心，LLM 属性提取 + 真实标签更新）

| 项        | 内容                                                                                                                                                      |          |                                                                                                                                                                                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **目标**   | 用属性轴偏好记忆替代 L_syn 的"可解释分解"角色：属性提取→强化-反思更新，绕开 E14 系列确认的 L_syn 阻断点                                                                                         |          |                                                                                                                                                                                                                                                                                                             |
| **机制**   | ① **属性提取器**：DeepSeek（deepseek-chat）读 item 标题+描述 → 输出 \`attribute: item                                                                                  | polarity | score`（照搬 `prompt.py:159/211` 模板格式，属性空间用 MMEACR 9 维默认或按品类裁剪）② **强化-反思**：正确性信号 = 真实 next-item 命中（`y_proxy = item_embeddings(target_pos[:,-1])` 已接线于 E15-TF trainers，复用）→ 命中强化（正属性权重↑）、未命中反思（负属性权重↑/衰减）③ **三段式门控**：`soft_fusion_memory` 思想（DIRECT≥0.5 / FUSION 0.3~0.5 / REJECT<0.3，`memory_manager.py:955\`） |
| **关键配置** | 属性提取仅对**训练集交互过的 item** 离线批量缓存（一次性成本，控制 API 调用量）；temperature=0.1（可解析性，同 MMEACR）；LLM 属性维度 K∈{5,9}；更新步长/门控阈值扫描                                             |          |                                                                                                                                                                                                                                                                                                             |
| **实现落点** | 新建 `baseline/PRISM/attribute_memory.py`（独立模块，不侵入 PRISM.py）；DeepSeek 调用复用 `skills/deepseek_summarizer.py` 的客户端模式（OpenAI SDK + base_url=api.deepseek.com） |          |                                                                                                                                                                                                                                                                                                             |
| **依赖**   | DeepSeek key + amazon-baby-mmssl item 标题（已有）                                                                                                            |          |                                                                                                                                                                                                                                                                                                             |
| **成功判定** | ① 机制门：属性提取成功率 >95%（正则解析），LLM 输出结构稳定；② 推荐门：加属性记忆 vs 不加（仅 e_u 画像）双 seed R@20 ≥ +2%；③ 可解释门：用户画像属性与真实交互的极性一致性（作为叙事证据，不作硬判据）                                 |          |                                                                                                                                                                                                                                                                                                             |

**为什么是核心**：这是唯一一条能承接 C1（PRISM 收口）后"叙事转型"的实验——把 PRISM 从"信息论分解"（已否证）转向"属性学记忆"（MMEACR 真实代码背书 + DeepSeek 落地）。即使推荐增益不达 +2%，属性画像本身是 MixRAGRec G 组 verbalize（G4）的前置资产。

### M3 e_u 多模态用户画像（P1.5，零 LLM，立即可做，M1/M2 的公共前置）

| 项        | 内容                                                                        |
| -------- | ------------------------------------------------------------------------- |
| **目标**   | 把"用户画像"从纯 ID 均值升级为多模态均值（C5 中特征有效的落点）                                      |
| **机制**   | `e_u = mean(CLIP_feat ⊕ SBERT_feat of user's interacted items)`（零外网，特征现成） |
| **对照**   | 纯 ID 均值（现 idea2 行为）vs 多模态均值 vs 属性加权均值（M2 产出的属性权重加权）                       |
| **实现落点** | `mm_align.py` 或独立脚本；产物喂给 M1 轨 2 与 M2 属性记忆                                 |
| **依赖**   | 无（纯 numpy 运算，Git Bash 可跑）                                                 |
| **成功判定** | 一致性指标（画像与 held-out 交互的余弦）显著 > 随机；作为 M1/M2 的输入验证                           |

### M4 LLM 推理轨评估通道（P2，DeepSeek 排序轨，G 组预备）

| 项        | 内容                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------- |
| **目标**   | 建立"LLM 排 ⊕ CF 排"的 RRF 评估框架，为 G 组（MixRAGRec GPU 线）铺路                                                     |
| **机制**   | DeepSeek 对 candidate_num=10 候选集排序（LLM 排序，照搬 `system_prompt_template_evaluation`），与 LightGCN++ 排 RRF 融合  |
| **关键配置** | candidate_num=10（MMEACR 默认）；评估集规模控制（subset 500 用户起步，控制成本）；批级重试（`AgentCF_Test_log-.py` process_batch 模式） |
| **依赖**   | DeepSeek key + M1 的 RRF 框架                                                                              |
| **成功判定** | 通道可用（冒烟）+ 融合后 R@20 ≥ CF 单轨（成本允许时再扩大样本）                                                                  |

**注意**：M4 是 G 组（GPU）的**评估侧预备**，不做训练回路（LLM 排序是推理轨的评估形式，不是新训练）。

## 3. 实验依赖与执行顺序

```
M3（e_u 画像，零 LLM，当天可出）──┐
                                  ├─→ M1（RRF 融合，轨2=e_u 画像）
M2-前置（DeepSeek 属性提取离线缓存）┴──→ M2（属性引导记忆，复用 M3 画像做锚点）→ M4（LLM 排评估通道）
```

| 步骤 | 内容                                      | 预计算力        | 前置    |
| -- | --------------------------------------- | ----------- | ----- |
| S1 | M3 e_u 画像落盘 + 一致性验证                     | CPU 分钟级     | 无     |
| S2 | M1 RRF 融合（轨2=SBERT/CLIP 均值 + e_u）k/w 扫描 | CPU 分钟级     | S1    |
| S3 | M2 属性提取离线缓存（DeepSeek，只对交互过 item）        | API 调用（一次性） | S1    |
| S4 | M2 强化-反思 + 三段式门控训练                      | CPU 小时级     | S3    |
| S5 | M4 LLM 排评估通道（subset）                    | CPU + API   | S1,S2 |

**红线（复用 C1 教训）**：任何实验的"机制主张"必须有**可归因判据**——M2 的推荐增益必须对比"仅 e_u 画像（M3）"而不是对比空基线，否则无法区分"属性记忆有用"还是"画像有用"。

## 5. 风险登记

| 风险                     | 概率 | 触发表现              | 缓解                                                                             |
| ---------------------- | -- | ----------------- | ------------------------------------------------------------------------------ |
| M2 属性提取成本失控            | 中  | API 调用量随交互数线性涨    | 只对训练集交互 item 离线缓存一次；batch 异步（Semaphore 模式照搬 `request.py`）；失败降级为规则属性            |
| M2 增益不达 +2%（重蹈 E15 覆辙） | 中高 | 双 seed R@20 无显著提升 | 提前声明：增益不达则退化为"属性画像=可解释叙事资产"（供 G4 verbalize），不硬撑推荐增益主张——**与 C1 同款诚实口径**         |
| LLM 属性噪声（幻觉属性）         | 中  | 提取成功率/极性一致性低      | temperature=0.1 + 正则校验 + 只保留与 item 标题共现的属性（facts-only，复用 title_factory 的防幻觉经验） |
| RRF 融合无增益（k/w 不敏感）     | 低中 | 融合 ≈ 单轨           | 判据已放宽（+2% 或 +0.5% 两档）；若确实无增益则记录"排名层融合在本数据上无边际贡献"，关闭该线（同样诚实收口）                  |

## 6. 一句话总结

> **PRISM 否证之后，下一轮实验锚定在"属性记忆 + 双轨融合"两条线上**：M3（e_u 多模态画像，零成本立即可跑）→ M1（RRF 双轨融合，把 C5 的"特征有效但学不到"变成排名层可拿到的增益）→ M2（属性引导记忆，DeepSeek 属性提取 + 真实标签强化-反思，替代 L_syn 的叙事角色）→ M4（LLM 排评估通道，G 组预备）。三条红线：**机制可归因**（对照必须隔离）、**同口径 R@20**（双 seed）、**增益不达即诚实退化为资产**（不重蹈观点②的叙事膨胀）。
